## Story Context

- **Goal:** G-002 — Dark Theme Footer Styling
- **Constraint:** C-001 — Only modify `index.html`; C-002 — No external CSS frameworks

## Design Decisions

### DD-001: Selector Strategy
**Decision:** Use `footer` element selector (not `#contact` ID).
**Rationale:**
- Only one footer element exists per HTML spec best practices
- Element selector is simpler and more semantic
- ID selector (`#contact`) adds unnecessary specificity
- Easier to maintain if more footers are added later

### DD-002: Background Color
**Decision:** Use `background: #0a0a0a` (slightly darker than body's `#111`).
**Rationale:**
- Creates subtle visual separation from main content
- Maintains dark theme consistency
- Provides contrast without being jarring
- Alternative: `#111` (same as body) is acceptable per requirements

### DD-003: Text and Link Colors
**Decision:** Use `color: #ccc` for text, inherit for links, add hover state.
**Rationale:**
- Slightly muted compared to body text (`#eee`) for visual hierarchy
- Links inherit color for consistency
- Hover state provides interactivity feedback

### DD-004: Spacing
**Decision:** Use `padding: 1rem; margin-top: 2rem`.
**Rationale:**
- Matches body padding (2rem) for alignment
- Margin provides separation from hero section
- Consistent with existing design language

## Contract

### CSS Structure Contract
```
GIVEN the index.html <style> block
WHEN the footer CSS rules are added
THEN:
  - A CSS rule targeting 'footer' exists in the <style> block
  - The rule includes a background property with a dark color value
  - The rule includes a color property with a light color value
  - The rule includes padding for visual spacing
  - No external stylesheets are linked (<link rel="stylesheet">)
  - No inline styles are added to the <footer> element
```

### Visual Contract
```
GIVEN the page is rendered in a browser
WHEN the user views the footer
THEN:
  - Footer background is visibly dark (distinct from transparent)
  - Footer text is light and readable
  - Footer email link is visible and matches theme
  - Footer has visual separation from content above
```

## Implementation Specification

### Location
**File:** `index.html`
**Insert at:** Line 9, after `.hero { ... }` rule, before `</style>`

### CSS to Add
```css
footer { background: #0a0a0a; color: #ccc; padding: 1rem; margin-top: 2rem; text-align: center; }
footer a { color: #00ff41; }
footer a:hover { text-decoration: underline; }
```

### Rationale for Each Property
| Property | Value | Purpose |
|----------|-------|---------|
| `background` | `#0a0a0a` | Dark background per R-002 |
| `color` | `#ccc` | Light text per R-002 |
| `padding` | `1rem` | Visual breathing room |
| `margin-top` | `2rem` | Separation from hero |
| `text-align` | `center` | Centered footer pattern |
| `footer a color` | `#00ff41` | Match hero accent color |
| `footer a:hover` | `underline` | Interaction feedback |

### Expected Result (Full Style Block)
```css
body { font-family: sans-serif; background: #111; color: #eee; padding: 2rem; }
.hero { border: 1px solid #00ff41; padding: 1rem; }
footer { background: #0a0a0a; color: #ccc; padding: 1rem; margin-top: 2rem; text-align: center; }
footer a { color: #00ff41; }
footer a:hover { text-decoration: underline; }
```

## Test Seeds

### TS-001: Footer CSS rule exists
- **Behavior:** Style block contains a footer selector
- **Input:** Parse index.html `<style>` content
- **Expected:** Pattern `footer\s*\{` matches
- **Command:** `grep -E 'footer\s*\{' index.html`

### TS-002: Background property present
- **Behavior:** Footer has dark background defined
- **Input:** Parse footer CSS rule
- **Expected:** `background` property exists with hex color
- **Command:** `grep -E 'footer.*\{[^}]*background' index.html`

### TS-003: Color property present
- **Behavior:** Footer has text color defined
- **Input:** Parse footer CSS rule
- **Expected:** `color` property exists
- **Command:** `grep -E 'footer.*\{[^}]*color' index.html`

### TS-004: No external stylesheets
- **Behavior:** C-002 constraint maintained
- **Input:** Parse index.html for link tags
- **Expected:** No `<link rel="stylesheet">` elements
- **Command:** `! grep -q '<link.*stylesheet' index.html && echo PASS`

### TS-005: No inline styles on footer
- **Behavior:** Styles are in style block, not inline
- **Input:** Parse footer element
- **Expected:** `<footer id="contact">` has no `style=` attribute
- **Command:** `! grep -q '<footer.*style=' index.html && echo PASS`

### TS-006: Footer link styling exists
- **Behavior:** Link color matches theme
- **Input:** Parse style block for footer link rule
- **Expected:** `footer a` selector exists
- **Command:** `grep -E 'footer\s+a\s*\{' index.html`

### Edge Cases

#### EC-001: Dark color validation
- **Behavior:** Background is actually dark (not light)
- **Verification:** Background hex value starts with #0, #1, #2, or #3
- **Command:** `grep -E 'footer.*background:\s*#[0-3]' index.html`

#### EC-002: Light text validation
- **Behavior:** Text color is actually light (not dark)
- **Verification:** Color hex value has high values (c, d, e, f in first position)
- **Command:** `grep -E 'footer.*color:\s*#[c-f]' index.html`
